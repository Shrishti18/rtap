# Wannier tight-binding Hamiltonians + flat-band candidates + structures

Three datasets, one directory. Everything below was fetched from open sources;
nothing paywalled was queried.

| | Dataset | What arrived | Size |
| --- | --- | --- | ---: |
| **1** | [JARVIS-WTB Wannier Hamiltonians](priority1_wannier_jarvis/) | **1,772 archives**, all containing `wannier90_hr.dat`, + full id→formula/space-group map | 13 GB |
| **2** | [Flat-band candidate lists](priority2_flatbands/) | **2,379 curated** materials (6,338 ICSDs), **345 top candidates** (949 ICSDs), **1,102 atomic** (1,830 ICSDs) | 133 MB |
| **3** | [CIFs for the Priority-2 candidates](priority3_cifs/) | **8,168 CIFs**, all with explicit symmetry operations | 37 MB |

## Priority 1 — Wannier tight-binding Hamiltonians

Garrity & Choudhary, *Sci. Data* **8**, 106 (2021);
figshare [10.6084/m9.figshare.c.5192276.v2](https://doi.org/10.6084/m9.figshare.c.5192276.v2).

* **1,772 / 1,772 archives downloaded, every one verified against the
  figshare MD5 and byte size. Zero failures.** (The paper says 1,771 — 1,406 3D
  + 365 2D; the deposit holds 1,407 3D, one more than the paper states.)
* **1,772 / 1,772 contain `wannier90_hr.dat`** and `wannier90.win`; 1,771 also
  contain `wannier90.wout` (`JVASP-6145` has none).
* **1,772 / 1,772 have formula + space group** —
  `jvasp_id_formula_spacegroup.csv`. 1,755 from the JARVIS-DFT `dft_3d`/`dft_2d`
  datasets via `jarvis-tools`, the other 17 derived from the deposited POSCAR
  with spglib; `metadata_source` says which. Also carries ICSD and Materials
  Project ids and `num_wann` per material.

The archives are kept zipped: unpacking only the `_hr.dat` files needs **69.5
GB** and this machine has 30 GB. That is the format figshare ships and the
bytes are intact — `priority1_wannier_jarvis/extract_hr_dat.py` unpacks all or
any subset. Format verified by parsing one in full: `JVASP-5` has 48 Wannier
functions × 441 R-points = 1,016,064 matrix elements, exactly as its header
declares.

## Priority 2 — flat-band candidates

Regnault *et al.*, *Nature* **603**, 824 (2022). Captured from two sources
because they disagree:

* **The Nature Supplementary Information** (both PDFs downloaded). Tables XI and
  XII were parsed from PDF word bounding boxes — `-layout` text is unusable
  here, since column positions are re-typeset per page and each row's ICSD cell
  is a multi-line block centred on its row. Yields exactly **2,379** and
  **1,102** rows.
* **The live [Materials Flatband Database](https://www.topologicalquantumchemistry.fr/flatbands/)**,
  walked entry by entry (8,168 records, 0 failures) and closed under each
  record's sibling-ICSD field.

The live database reproduces the paper's headline numbers **exactly** —
2,379 curated / 6,338 ICSDs, 345 best / 949 ICSDs — so it is the set to prefer,
and all 2,379 SI rows were matched back to it on composition + space group.

Two places where the *printed* SI disagrees with its own prose, documented in
[priority2_flatbands/README.md](priority2_flatbands/README.md): the table flags
**339** top candidates where the text says 345, and the ICSD cells as printed
yield 6,262 rather than 6,338. Both are defects in the published table; the
verified columns resolve them.

## Priority 3 — structures

**8,168 CIFs, every one with an explicit `_symmetry_equiv_pos_as_xyz` loop** —
covering *every* ICSD entry of *every* Priority-2 candidate, none missing.

These are the original ICSD CIFs, served publicly by the flat-band database and
matched **by ICSD id**, so no formula/space-group guessing was involved. They
carry a FIZ Karlsruhe copyright notice — see
[priority3_cifs/README.md](priority3_cifs/README.md) before redistributing, and
for the open-licence alternatives (a Materials Project link is recorded for all
8,168 entries).

## Paywalled sources — not used

ICSD (FIZ Karlsruhe) and Elsevier were never queried. Everything here came from
figshare, Nature's open supplementary files, the public flat-band database, and
`jarvis-tools`.

## Reproducing

Bulk data (`zips/`, `records/`, `extracted_small/`, the JARVIS-DFT dumps) is
gitignored — too large for git, and every byte is regenerated by the scripts,
which are resumable and checksum-verified:

```bash
cd priority1_wannier_jarvis && python3 download_figshare.py && python3 build_manifest.py
cd ../priority2_flatbands   && python3 parse_si_tables.py \
                            && python3 fetch_flatband_records.py seed_icsds.txt \
                            && python3 finalize_flatbands.py
```
